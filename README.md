# AutoDayTrading

## 0. 먼저 읽을 것

이 프로그램은 원칙을 지켜가며 매매를 대신 실행하는 도구입니다. **기대수익을
만들어주지 않습니다.** 규칙을 지키는 것과 돈을 버는 것은 다른 문제입니다.

- 왕복 비용(수수료 0.015%×2 + 거래세 0.15%)은 **0.180%**입니다. 이 비용을
  이기지 못하는 설정(익절폭이 왕복 비용의 2배 미만)은 실행 자체를 거부합니다.
- 이 프로그램은 규칙을 지켜주는 도구일 뿐, 기대수익을 만들어주지 않습니다.
  시장이 나쁘면 규칙을 완벽히 지켜도 손실이 납니다.
- **잃어도 생활에 지장 없는 금액으로만** 배정하세요. `capital.allocation` 은
  계좌 전체가 아니라 이 프로그램에 맡길 금액입니다.

## 1. 시작하기

1. `AutoDayTrading.exe` 를 더블클릭합니다.
2. 트레이 아이콘이 뜨면 실행된 것입니다. **윈도우 11 은 새 트레이 아이콘을
   기본으로 숨깁니다** — 작업표시줄 오른쪽의 `^` (숨겨진 아이콘 표시)를
   눌러 확인하세요.
3. 아이콘을 더블클릭하거나 메뉴의 "대시보드 열기"를 누르면 브라우저가
   열립니다.
4. 처음 접속하면 비밀번호(숫자 6자리, 기본값 `123456`)를 입력해야 합니다.
   자세한 내용은 [14. 로그인과 접속 보안](#14-로그인과-접속-보안)을 보세요.
5. 회사·학교망처럼 프록시가 있는 환경이면 `pip install truststore` 로
   해결되는 경우가 많습니다 (exe 에는 이미 포함되어 있습니다).
6. 뭔가 이상하면 먼저 진단하세요:
   ```
   AutoDayTrading.exe --check
   ```
   파일·패키지·포트·설정·연결 상태를 한 번에 보여줍니다.

## 2. 화면 구성

화면은 왼쪽 **사이드바**(데스크톱·태블릿)와 하단 **탭바**(모바일)로
오갑니다. 16개 화면이 아래 네 그룹으로 묶여 있습니다.

| 그룹 | 화면 |
|---|---|
| 매매 | 대시보드 · 종목 선정 · 속보 · 시장 |
| 기록 | 성과 · 매매일지 · 시장 평가 |
| 개선 | 소개 · 월간 리뷰 · 실험실 · 매매 기법 · 매매원칙 · 릴리즈 노트 |
| 설정 | 준비·연결 · 테마 · 설정 |

[설정] 그룹은 로그인 세션이 있어도 들어갈 때마다 비밀번호를 한 번 더
확인합니다(잠금 안 된 화면을 자리 비운 사이 다른 사람이 만지는 것을
막기 위해서입니다).

## 3. 종목을 어떻게 고르는가 (국내주식)

종목은 사람이 고르지 않습니다. 다음 순서로 프로그램이 뽑습니다.

1. **테마 인정** — `themes.yaml` 에 적힌 테마 중, 구성 종목 **2개 이상이
   함께 +3% 이상 상승**해야 그 테마를 오늘의 주도 테마로 인정합니다.
   한 종목만 튀는 것은 테마가 아니라 개별 이슈로 봅니다.
2. **테마 강도 계산**
   ```
   테마 점수 = 동반상승 종목수 × 상승률 중앙값 × log10(거래대금)
   ```
   상승 종목이 많고, 상승폭이 크고, 거래대금이 클수록 점수가 높습니다.
3. **대장주 우선** — 인정된 테마 안에서 거래대금이 가장 큰 종목을
   우선합니다.
4. **필터링** — 가격대·상승률·거래대금·유의종목 조건을 모두 통과해야
   후보가 됩니다.

**★ 선정 과정이 전부 화면에 보입니다.** [종목 선정] 화면에는 오늘 인정된
테마뿐 아니라 **탈락한 테마와 그 사유**, 테마 사전에 있는 **모든 종목**이
선정/탈락 여부와 함께 표로 나옵니다. "왜 안 샀는지"를 항상 확인할 수
있습니다. (해외주식·스윙은 테마 대신 관심종목 목록에서 고릅니다 — 각각
[9. 해외주식 자동매매](#9-해외주식-미국-자동매매), [11. 스윙 매매](#11-스윙-매매) 참고.)

## 4. 왜 샀는지 · 왜 안 샀는지

모든 판단은 [매매일지]에 사람이 읽을 수 있는 문장으로 남습니다.

```
[09:31:12] (buy) 052690 052690을 74,900원에 18주 샀습니다.
  [왜 이 종목인가] '원자력_전력기기' 테마가 오늘 1위입니다
  (2종목 동반 상승, 중앙값 +4.70%, 대금 301억). 그 안에서 이 종목은
  대장주이고, 현재 74,677원(+4.33%), 거래대금 217억으로 가격대·상승률·
  거래대금·유의종목 필터를 모두 통과했습니다.
  [왜 지금인가] 같은 테마 종목이 동시에 오르는 진짜 테마 장세에서
  유동성이 가장 큰 대장주를 잡는다. 테마 내 상승 종목 수 2개,
  테마 순위 1위, 테마 강도 +4.70% 조건을 확인했습니다.
  손절 73,028원 / 목표 78,645원을 함께 걸었습니다(증권사 서버에 OCO로
  등록해서 프로그램이 꺼져도 손절이 살아있습니다).
```

"왜 이 종목인가"(선정 이유)와 "왜 지금인가"(진입 신호)는 서로 다른 질문이라
항상 따로 답합니다. 조건이 바뀌어 판정이 뒤집히면("통과 못 했다가 통과했다")
그 변화도 기록에 남아 "직전 평가 대비 무엇이 바뀌었나"를 되짚을 수 있습니다.

## 5. 매매 기법

문헌으로 검증된 기법만 씁니다. 기법마다 출처(사람·책·연도)가 화면과
코드에 남아 있어, 지어낸 규칙과 구분할 수 있습니다. 국내·해외·스윙주식은
같은 기법 체계(`daytrader/playbook.py`)를 공유합니다. 암호화폐는 24시간
시장·상하한가 없음 등 근본적으로 다른 조건 때문에 변동성 돌파 기법만
따로 씁니다 — [10. 암호화폐(빗썸) 자동매매](#10-암호화폐빗썸-자동매매) 참고.

### 진입 (5종 기본 + 2종 추가)

| 기법 | 원전 |
|---|---|
| 돌파 추종 (breakout) | 돈치안 채널(Richard Donchian, 1960년대) · 다베스 박스(Nicolas Darvas, 1960) |
| 테마 대장주 (theme_leader) | 상대강도 주도주 — William O'Neil, CAN SLIM (1988) |
| VWAP 눌림목 (vwap_pullback) | VWAP — Berkowitz·Logue·Noser (1988, Journal of Finance) |
| 시초 갭 돌파 (open_gap) | 갭 앤 고(Gap and Go) — 데이트레이딩 표준 · 개장 레인지 돌파(Crabel, 1990)의 갭 버전. 국내 09:00~09:40 전용, 진입 기법에서 켜야 작동 |
| 장 막판 상승 지속 (close_squeeze) | 마감 모멘텀 — Heston·Korajczyk·Sadka (2010, Journal of Finance). 국내 14:30~15:00 전용, 진입 기법에서 켜야 작동 |
| VWAP 재탈환 (vwap_reclaim) | VWAP — Berkowitz·Logue·Noser (1988) · 실패한 하락 반전(Failed Breakdown) — Al Brooks (2009). 기본은 꺼짐 - 설정에서 켜서 모의매매로 검증 |
| 개장 레인지 돌파 (orb) | 오프닝 레인지 브레이크아웃 — Toby Crabel (1990) |
| 거래량 마름 후 분출 (volume_dry_pop) | 변동성 수축 패턴(VCP) — Mark Minervini (2013) · NR7 — Crabel (1990) |
| 강세 깃발형 (bull_flag) | Edwards & Magee (1948) |
| 이동평균 눌림목 (ma_pullback) | '홀리 그레일' — Raschke & Connors, 『Street Smarts』(1995) |

진입은 켜진 순서대로 평가해 **처음 통과한 기법으로** 삽니다.

### 청산과 우선순위

손실을 막는 규칙이 항상 먼저입니다:

```
장 마감 강제청산 > 고정 손절 > ATR 손절 > 고정 익절
  > 추적 손절 > 모멘텀 소멸 > 시간 손절
```

**고정 손절·익절(fixed)은 끌 수 없습니다.** 손절 없는 매매는 만들 수
없도록 설정 화면에서부터 막아 둡니다.

## 6. 돈을 덜 잃기 위한 장치 (국내주식 기본값)

아래 값은 `config.yaml` 의 국내주식 기본값이며, 해외주식·암호화폐·스윙은
각자의 설정 섹션(`overseas`/`crypto`/`swing`)에 따로 있습니다 — 값이 다를
수 있습니다(예: 스윙은 손절 10%·익절 40%처럼 폭을 훨씬 넓게 잡습니다).

| 장치 | 기본값 | 왜 |
|---|---|---|
| 1회 투입 | 배정 자본의 30% (`sizing.initial_ratio`) | 한 번에 다 넣지 않고 신호 강도에 따라 나눠 들어가기 위해서 |
| 동시 보유 | 최대 2종목 (`capital.max_positions`) | 종목이 많아지면 감시가 허술해진다 |
| 손실 뒤 크기 축소 | 정상의 50% | 잃고 있을 때 키우는 건 물타기, 계좌가 가장 빨리 망가지는 길 |
| 연속 손절 한도 | 2회 | 오늘은 시장과 안 맞는다는 신호로 본다 |
| 일일 손실 한도 | 3% | 손실 난 날 더 하려는 충동을 막는다 |
| 주간 손실 한도 | 6% | 이번 주는 더 하지 않고 다음 주에 다시 시작 |
| 일일 최대 거래 | 50회 (`risk.daily_max_trades`) | 과매매는 비용으로 계좌를 갉아먹는다 |
| 최대 슬리피지 | 0.5% | 예상가보다 많이 밀리면 주문을 포기한다 |
| 재진입 금지 시간 | 20분 | 손절 후 감정적 복구매매 방지 |
| 최소 주문 금액 | 10,000원 | 너무 작은 주문은 수수료 비중이 커진다 |
| 시세 끊김 감지 | 3회 연속 실패 | 시세를 못 보는 상태에서 사는 것은 눈 감고 사는 것 |
| 최대 보유 시간 | 4,320분(3일) (`exit.max_hold_minutes`) | 장중 시간손절 기준. 다음 날로 넘기는 것은 아래 조건부 오버나잇 규칙만 따른다 |
| 조건부 오버나잇 | 이익 2% 이상만, 최대 1일 | 무조건 넘기지 않는다. 비용을 뺀 뒤에도 기준 이상 이익인 포지션만 손절선을 본전으로 올려 하루 넘긴다 |

**★ 오버나잇(하루를 넘겨 보유하는 것)은 조건부로만 허용됩니다**
(`exit.allow_overnight: true`). 장 마감 강제청산(`force_close_time`) 때
포지션마다 다음 순서로 판단합니다.

1. 이미 하루 넘긴 포지션이면 무조건 청산합니다(`exit.overnight_max_days: 1`).
2. 금요일이나 휴장 전날이면 청산합니다(`exit.overnight_skip_before_holiday`).
3. 비용을 뺀 수익이 `exit.overnight_min_profit_pct`(기본 2%)보다 작으면 청산합니다.
4. 조건을 모두 통과하면 손절선을 본전(매수가 + 왕복비용)으로 올리고 서버
   OCO를 다시 걸어 하루 넘깁니다(`exit.overnight_breakeven_stop`). OCO를
   다시 걸지 못하면 안전을 위해 넘기지 않고 청산합니다.

넘긴 포지션은 다음 날 개장 직후 OCO를 다시 등록합니다(서버 OCO는 당일만
유효합니다). 데이트레이딩만 원한다면 [설정]에서 `allow_overnight` 을 끄세요.

## 7. 실거래 안전장치

- **계좌가 진실이다.** 내부 상태와 실제 계좌가 다르면, 내부 상태를 계좌
  기준으로 고치고 그 사실을 원장·일지에 남깁니다. 조용히 고치지 않습니다.
- **주문은 두 번 나가지 않는다.** 응답을 못 받으면(타임아웃 등) 재전송
  대신 계좌를 조회해 확인합니다. 그래도 못 찾으면 매매를 멈추고
  "토스 앱에서 직접 확인하세요"라고 알립니다.
- **서버 OCO 체결 감지.** 프로그램이 꺼져 있는 동안 서버에 걸어둔
  손절/익절이 체결됐을 수 있습니다. 도는 중 주기적으로 확인해 내부
  상태를 맞춥니다.
- **남의 포지션을 건드리지 않는다.** 사용자가 직접 산 종목, 이 프로그램이
  내지 않은 주문(`dt-` 로 시작하지 않는 주문)은 절대 건드리지 않습니다.
  암호화폐(빗썸)도 같은 원칙입니다 — 이 프로그램이 직접 사서 기록해 두지
  않은 코인은 계좌에 있어도 절대 매도하지 않습니다.
- **사전 점검 12항목 이상.** 실거래를 시작하기 전 인증·계좌·휴장일·
  매수가능금액·미체결 주문·테마 종목 검증·비용 설정 등을 확인합니다.
  하나라도 막히면 시작할 수 없습니다.
- **조건부 오버나이트, 실패하면 넘기지 않는다.** `exit.allow_overnight` 를
  켜도 모든 포지션을 넘기지 않습니다 - 장 마감 시점에 비용을 뺀 평가손익이
  `exit.overnight_min_profit_pct`(기본 2%) 이상이고, 휴장 전날이 아닐 때만
  최대 `exit.overnight_max_days`(현재 1일) 넘깁니다. 넘기는 포지션은
  손절선을 본전으로 올려 서버 OCO 를 다시 거는데, 그 **재설정이 실패하면
  안전을 위해 넘기지 않고 그 자리에서 청산**합니다. 넘긴 포지션은 다음
  장마감에 이익이 나도 무조건 정리합니다(다시 넘기지 않음). 서버 OCO 는
  하루짜리라, 새 거래일이 시작되면 넘긴 포지션의 OCO 를 자동으로 다시
  겁니다 - 그 재등록에도 실패하면 일지·알림으로 남기니, 실거래에서는
  개장 직후 알림을 꼭 확인하세요.

| `paper` | 실시간 시세로 모의 주문을 냅니다. 실제 체결은 없습니다. |
| `live` | 실제 계좌로 실주문을 냅니다. |

최상위 `mode` 는 국내주식 엔진의 모드입니다. 해외주식(`overseas.mode`)·
암호화폐(`crypto.mode`)·스윙(`swing.mode`)은 각자 독립된 모드 값을
가집니다 — 국내주식이 `live` 여도 암호화폐는 `paper` 로 연습만 할 수
있습니다(그 반대도 가능합니다). 네 엔진 중 실제로 실주문을 내는
(`live`) 엔진은 항상 하나로 제한됩니다.

**★ `web`/`paper` 모드에서 토스 API 키가 없으면** 인터넷 공개 시세(네이버)로
넘어가는데, 여기엔 분명한 한계가 있습니다:

- 분봉에 **시가·고가·저가가 없습니다.** 종가로 근사하기 때문에 '최근 N봉
  고가 돌파' 같은 판정이 실제보다 보수적으로 동작합니다.
- 시장 전체 랭킹을 받을 수 없어 `themes.yaml` 에 적힌 종목 안에서만
  테마를 찾습니다.
- 매수 유의사항(투자경고·단기과열 등)을 받을 수 없습니다.

[준비·연결] 화면에서 지금 어떤 시세 소스를 쓰고 있는지, 그 한계가
무엇인지 항상 확인할 수 있습니다.

기본 설정은 `overseas.enabled: false`, `overseas.mode: web`(관찰만) 입니다

## 10. 암호화폐(빗썸) 자동매매

**빗썸(Bithumb)** Open API 2.0 을 통해 원화 마켓(KRW-BTC 등)에서
매매합니다. 24시간 쉬지 않는 시장이라 "장 마감"이 없고, 상하한가도
없습니다 — 국내·해외주식과 근본적으로 조건이 달라 다음 세 가지가
다릅니다:

- **진입 기법** — 변동성 돌파(Volatility Breakout, Larry Williams 의
  주식·선물용 기법을 국내 코인 트레이더들이 응용한 형태) 하나만 씁니다.
  학술 논문이 아니라 실전 운용 사례로 뒷받침된 "커뮤니티 검증" 기법이라는
  점을 화면에도 그대로 밝힙니다.
- **종목 선정** — 코인 하나하나가 이미 각자 하나의 시장이라 "테마"
  스크리닝이 의미가 없습니다. `crypto.watchlist`(기본: BTC·ETH·XRP)에
  거래대금 상위 코인을 자동으로 더할 수 있습니다(`auto_top_volume`).
- **매도 제한** — 이 엔진이 직접 사서 장부에 기록해 두지 않은 코인은
  계좌에 있어도 절대 매도하지 않습니다(`NotOwnedError`로 구조적으로
  거부합니다).

기본 설정은 `crypto.enabled: false`, `crypto.mode: paper`(모의매매) 입니다
— [준비·연결] 화면에서 빗썸 API 키를 등록하고 켤 수 있습니다.

★ `daytrader/crypto_playbook.py` 는 암호화폐 전용 기법을 따로 두던 옛
모듈입니다. 지금은 암호화폐도 국내주식과 같은 `playbook.py` 를 재사용해
더 이상 실제 매매 경로에서 쓰이지 않지만, 자체 오프라인 테스트
(`tests/test_crypto_playbook.py`)가 남아 있어 파일은 그대로 두었습니다.

## 11. 스윙 매매

며칠~몇 주 단위로 보유하는 별도의 매매 방식입니다. 국내주식·해외주식·
암호화폐 세 시장의 포지션을 시장별 on/off 없이 **하나의 엔진**이 함께
관리합니다(포지션마다 어느 시장 것인지 표시만 다릅니다).

- **시간축** — 1분봉이 아니라 **일봉**으로 돕니다.
- **기법** — 이동평균 눌림목·돌파·골든크로스 3종(`swing_ma_pullback`/
  `swing_breakout`/`swing_golden_cross`, 모두 일봉 전용)만 씁니다. 장
  마감 강제청산은 스윙에서는 절대 발동하지 않습니다.
- **종목 선정** — 국내는 단타와 같은 테마 후보 풀 + `swing.watchlist`,
  해외는 `overseas.watchlist` + `swing.overseas_watchlist`, 암호화폐는
  `swing.crypto_watchlist` 에서 고릅니다.
- **손절·익절 폭** — 단타보다 훨씬 넓습니다(기본 손절 10%, 익절 40%,
  최대 보유 60일).

기본 설정은 `swing.enabled: true`, `swing.mode: paper`(모의매매) 입니다.

## 14. 로그인과 접속 보안

이 서버에는 인증이 있습니다 — 다만 계좌를 움직일 수 있는 프로그램이니
그 인증을 어떻게 강화할 수 있는지, 그리고 어디까지 안전한지 정확히
알아 두세요.

- **비밀번호(숫자 6자리)** — 첫 접속 시 입력합니다. 기본값은
  `123456` 이고, 로그인 후 화면 위쪽에 경고 배너가 계속 뜹니다.
  **가장 먼저 [준비·연결] → 외부 연동에서 이 값을 바꾸세요.**
- **서명된 세션 쿠키** — 로그인에 성공하면 30일짜리 서명 쿠키를
  내려줍니다(HttpOnly·SameSite=Strict, HTTPS 로 접속하면 Secure도 붙습니다).
  비밀번호를 바꾸면 그 순간 예전에 발급된 쿠키는 전부 무효가 됩니다.
- **새 기기 승인** — 처음 보는 IP·기기는 비밀번호가 맞아도 곧바로
  들어오지 못하고, 서버가 도는 그 PC 에서 `/admin` 페이지로 직접
  승인해야 합니다(그 PC 에서 스스로 연 브라우저는 예외 없이 바로
  들어갑니다).
- **민감한 동작 재확인(step-up confirm)** — 세션이 있어도 [설정] 그룹에
  들어가거나 자동매매를 시작/정지할 때는 비밀번호를 한 번 더 입력해야
  합니다. 자리를 비운 사이 잠금 안 된 화면을 남이 만지는 것을 막기
  위해서입니다.
- **Host·Origin 검사** — 알려진 이름(localhost·IP·Tailscale 이름)이
  아닌 Host 헤더로 오는 요청, 다른 사이트에서 보낸 것으로 보이는 쓰기
  요청은 서버가 자체적으로 거부합니다(DNS 리바인딩·CSRF 방어).

**★ 그래도 이 서버를 인터넷에 그대로 노출하지 마세요.** 기본적으로
`http://127.0.0.1:8000` 같은 로컬 주소로만 열도록 되어 있고, 다른 이름
(외부에서 접속 가능한 도메인 등)으로 열면 화면에 경고가 뜹니다. 다른
기기·외부에서 보고 싶다면:

- **HTTPS 로만 노출하세요** — 예를 들어 [Tailscale
  serve](https://tailscale.com/kb/1242/tailscale-serve)를 쓰면 자신의
  Tailscale 네트워크 안에서만, TLS 로 감싸서 접속할 수 있습니다. 평문
  HTTP 로 포트를 그대로 전달(포트포워딩)하면 비밀번호와 세션 쿠키가
  네트워크 중간에서 그대로 노출될 수 있습니다.
- SSH 터널도 같은 목적으로 쓸 수 있습니다:
  ```
  ssh -L 8000:127.0.0.1:8000 사용자@집컴퓨터
  ```
  이러면 터널 반대편에서만 `127.0.0.1:8000` 으로 접속할 수 있습니다.
- 둘 중 어느 방법을 쓰든, **기본 비밀번호(123456)는 반드시 바꾸세요.**
  누구나 아는 값이라 인증이 사실상 없는 것과 같습니다.

## 16. 매매기록·로그 저장(SQLite)

매매기록(원장·매매일지·주문의도 등)과 애플리케이션 로그는 `state\daytrader.db`
파일 하나(SQLite)에 저장됩니다. 예전에는 종류별로 JSONL 파일 하나씩(`ledger.jsonl`,
`decisions.jsonl`, `orders.jsonl` 등)에 한 줄씩 append 했는데, 조회할 때마다 파일
전체를 열어 한 줄씩 다시 파싱해야 해서 기록이 쌓일수록(매매일지 하나가 1.8MB까지
자란 적도 있습니다) 화면이 느려졌습니다. 지금은 인덱스가 걸린 SQLite 표에 담아,
기록이 아무리 쌓여도 필요한 몇 줄만 빠르게 찾습니다.

**왜 SQLite 인가.** Postgres·MySQL 같은 서버형 DB는 별도 프로세스·설치·포트가
필요해 "exe 하나로 실행되는 프로그램"이라는 이 프로젝트의 원칙과 맞지 않습니다.
SQLite는 파이썬 표준 라이브러리(`sqlite3`)에 포함돼 있어 **새 패키지 설치가 전혀
필요 없고**, 파일 하나뿐이라 백업·이동이 간단하며, WAL(Write-Ahead Log) 모드로
켜져 있어 매매 기록을 쓰는 동안에도 대시보드가 읽는 것을 막지 않습니다. 무료이고
가장 단순한 선택지라 골랐습니다.

**무엇이 저장되나.** 거래 원장(`trades`)·일별 잔고(`equity`)·매매일지(`journal`,
매수·매도·종목선정·계좌대조 등)·주문의도(`order_intents`, 국내·해외·암호화폐를
`book` 컬럼으로 구분해 한 표에 같이 담되 서로 안 섞입니다)·기법 백테스트 실행
기록·시장 평가(시황 요약) 발송 이력·복기(월간 리뷰) 반영 이력·계좌 대조 불일치
기록·뉴스가드 AI 호출 기록·애플리케이션 로그(`app_log`, WARNING 이상)가
`daytrader.db` 안의 각자 표에 들어갑니다. 각 표는 검색·정렬에 쓰는 필드(시각·
날짜·모드·기법·종목 등)를 인덱스가 걸린 컬럼으로 따로 두고, 원본 레코드 전체를
JSON 그대로 담는 컬럼도 함께 가지고 있어 스키마를 넓혀가는 동안에도 어떤 값도
잃지 않습니다.

**주문의도만 더 엄격합니다.** 주문을 보내기 전에 그 의도를 먼저 표에 적어 두는
것은 "타임아웃이 나도 이중 주문을 내지 않기 위한" 안전장치입니다(7장 참고). 이
표에 쓸 때만 `synchronous=FULL`로 커밋이 디스크에 완전히 내려갔는지(fsync)까지
확인한 뒤 되돌립니다 - 정전이나 강제종료 직후에도 "방금 주문을 보내려 했는지"를
절대 잃지 않기 위해서입니다. 다른 표는 WAL + `synchronous=NORMAL`로 충분히
빠르고 안전합니다.

**기존 JSONL 기록은 자동으로 옮겨집니다.** 업데이트한 버전을 처음 실행하면
`state\` 안의 기존 JSONL·일부 JSON 파일(호출 기록 등)을 한 번만 읽어
`daytrader.db`로 옮기고, 콘솔·로그에 무엇을 몇 건 옮겼는지 한글로 요약해
보여줍니다. 옮기는 도중 문제가 생겨도(정전 등) 원본 파일은 그대로 남아 있어
다음 실행 때 처음부터 다시 시도합니다 — 프로그램을 여러 번 다시 켜도 기록이
두 번 들어가지 않습니다. 옮기고 나면 원본은 **지우지 않고** `<파일명>.migrated`
로 이름만 바꿔 남겨 둡니다(필요하면 직접 열어볼 수 있습니다).

**애플리케이션 로그.** 진단용 회전 텍스트 로그(`logs\daytrader.log`,
`logs\run.log`, 10MB × 5개)는 그대로 남아 있습니다. 그와 별개로 WARNING 이상의
로그는 `daytrader.db`의 `app_log` 표에도 남아, 화면의 실시간 로그창(최근
2000건)보다 오래된 경고·오류도 나중에 날짜·레벨로 다시 찾아볼 수 있습니다
(`/api/logs/history`). 보관 기간은 기본 90일이고, 매일 자동으로 그보다 오래된
기록을 정리합니다. DB 쓰기가 실패해도(디스크 꽉 참 등) 조용히 그 줄만 버릴 뿐,
매매나 화면 응답을 막지 않습니다.

**백업.** `daytrader.db`도 `state\` 폴더 밑에 있으므로 `build_exe.bat`의 기존
`state\` 백업(재빌드 시 자동 백업·복원)에 그대로 포함됩니다. 다만 **프로그램이
켜져 있는 동안에는 `daytrader.db` 파일을 탐색기 복사나 `robocopy` 등으로 직접
복사하지 마세요** — WAL에 아직 합쳐지지 않은 최근 기록이 빠지거나 파일이 중간
상태로 찍힐 수 있습니다. 실행 중에도 안전한 복사본이 필요하면
`python run.py db-backup` 명령을 쓰세요(SQLite의 온라인 백업 기능을 사용해
`state\daytrader-backup-<시각>.db`를 만듭니다).

**유지보수.** 일요일마다 유휴 상태에서 `VACUUM`/`ANALYZE`를 한 번씩 돌려 파일
크기와 조회 계획을 정리합니다(장중과 겹치면 조용히 건너뛰고 다음 주에 다시
시도합니다). 20만 건 규모의 기록으로 확인한 결과, 최근 로그 200줄 조회는
수 ms, 오늘 거래 건수 조회는 1ms 미만, 한 달치 기법별 통계(SQL 집계)는
100ms 안팎으로 나왔습니다(정확한 수치는 `tests/test_db.py`를 실행해 보세요).
